# Applied econometrics

This skill turns an economic question into an estimated, diagnosed and defensible answer, and explains or audits such answers. The value is in the **rigor of the process**: anyone can run `sm.OLS(...).fit()`; what makes an analysis reliable is the specification, the assumption tests, the identification strategy and honesty about what the model does not prove. Methods follow Wooldridge, Greene, Hansen, Angrist-Pischke, Cameron-Trivedi, Hamilton, Chernozhukov et al. and EconML (`references/bibliography.md`).

Answer in the user's language, including the short progress messages between steps (these instructions are in English; do not drift into another language mid-task), and keep its accents in the scripts and logs you write. In a terminal (Claude Code) write formulas in plain text with Unicode symbols, not LaTeX, and use no HTML; LaTeX is for the app, notebooks and documents.

## 3. Consultant workflow

Full detail, code and the diagnostic order are in `references/workflow.md`. Explain each step and why it is done.

0. **Study card** before any estimate: question, estimand, design, identifying assumption in words, y, X (effect modifiers), W (confounders), Z (instruments), data, threats, robustness plan.
1. **Frame** the hypothesis and expected signs; classify the goal (effect, causal effect, heterogeneity, forecast).
2. **Identify the structure** of the data (table above).
3. **Obtain and audit** the data: source and code, frequency, nominal vs real, breaks, missing values (`data_prep.missing_report`), N per parameter; describe every model variable (`inference.describe_dist`: shape, outliers).
4. **Specify and estimate**: the simplest model that answers the question; robust SEs by default.
5. **Diagnose** in order: functional form, heteroskedasticity, autocorrelation, ARCH, normality, collinearity, influence, stationarity, stability, exogeneity.
6. **Test robustness**: at least two variations (specification, subsample, estimator, definition, sensitivity to unobserved confounding).
7. **Interpret and report**: answer with magnitude and interval, data, model, results, diagnostics, robustness, limitations.

## 4. Non-negotiable rules

Full versions and reasons in `references/interpretation-rules.md`; rules for a single domain (betas, EVT and FRTB backtests, two-sample tests and proportions, unit roots and filters, VAR/VECM, GARCH, DiD details) stay in its sections by version.

- **Design before data**: choose the estimand, design, covariates, bandwidths and windows before looking at outcomes. Choose controls with a causal graph (`dag.adjustment_report`): never mediators, colliders, post-treatment variables or instruments. Plan power (`simulation.mde_did`/`power_did_sim`) and report the MDE next to an insignificant effect.
- **DiD**: first run `causal.did_design` on the treatment column and relay its design; a reversible treatment or a dose never enters as `gvar`, and in "other" designs (treatment changing every period) say that the TWFE coefficient is not a robust causal effect (`causal.twfe_weights`). For staggered adoption, report `att_gt` with its joint pre-trend test and `causal.did_compare` against `did_imputation` (same `control`; it runs without covariates); a gap at alpha is a finding. Ask whether the adoption date is exact (and its source), announced in advance or gradual; run `causal.did_timing_sensitivity` next to `att_gt`; relay any timing WARNING in plain words. When parallel trends need covariates, use `att_gt(covariates=[...])` (levels, doubly robust), never covariates in a TWFE regression (hidden linearity bias); test common covariate effects with `causal.ccc_test` and, for an existing TWFE, run `causal.twfe_covariate_diagnostic` (its controls in `covariates`, the valid pre-treatment ones in `cs_covariates`) and `causal.bacon_decomposition`. When treatment varies at a higher level than the unit (a state law, municipal data), pass `cluster=` the assignment level to `att_gt` and its date checks; never aggregate to that level only to cluster (it changes the estimand).
- **Robust SEs by default** (HC3; HAC for time series). **Cluster where the regressor of interest varies** (a judge's sex: by judge, not by court), the same level in text and code; report the number of clusters; with fewer than ~40, add `estimation.wild_cluster_bootstrap`; with very few **treated** clusters, also `causal.randomization_inference`.
- **Association is not causation**: causal language only with an identification strategy; Granger causality is predictive precedence; say which way remaining bias probably goes.
- **One alpha per analysis**: pass the analysis's `alpha` to every threshold (`reporting.cross_check`, unit-root verdicts); never mix a 5% test with a hard-coded 10% or 1.96. **Declare the family of tests** before looking at results and adjust (`inference.adjust_pvalues`); report how many tests were run. Robust Wald tests with many restrictions over-reject with their χ² reference: use a wild bootstrap under the null (as `ccc_test` does) or say the p-value is anticonservative.
- **Not rejecting H0 is not evidence for H0**: write "does not reject", never "H0 is accepted" or "there is no effect"; give the interval and the effect the test could have detected (`inference.power_curve`, `simulation.power_mde`).
- **Statistical is not economic significance**: magnitude and interval, 2-3 significant digits, forecasts with intervals.
- **Interpret by functional form** (log-log elasticity, log-lin 100*(e^b - 1)%); **average marginal effects** in nonlinear models (Tobit: say which margin); **long-run effects** with delta-method SEs for lags; **prediction vs confidence intervals**, with smearing for log-y.
- **No look-ahead** in anything used to forecast, signal or manage risk at time t.
- **LLM-coded variables are measurements with error**: hand-code a random sample with known probabilities and use `text_data.dsl_regression`; report naive and corrected side by side.
- **Segmented logit**: benchmarks must contain every regressor of the leaf model; report segments only if they recur across seeds.
- **Heterogeneous effects only with evidence**: `hte.blp_test` rejects and `hte.gates` separates groups, on out-of-fold predictions; compare a linear and a flexible model; value policies on held-out units.
- **Run more than one model** for causal claims (simple structural and flexible); disagreement is a finding. Claims from observed controls carry a sensitivity analysis benchmarked on observed covariates (`specification.sensitivity`; `causal.dml_sensitivity` + `dml_benchmark`).
- **Advice must match the tools**: never recommend a step and show code that does something else; if no function exists, say so and write the code.
- **Deliver code, not only a plan.** Every answer that recommends an analysis names the skill's function for each step (Stata/R only as a complement) and ends with a runnable script that calls those functions: run it on the user's data, or, with no data yet, on simulated data with the same structure (same units, variables and N), so the user only swaps the file. Show the code or deliver it as a downloadable file; never point to an internal sandbox path. Start the script with the locator block in `references/interpretation-rules.md` ("Script skeleton"): it takes `ECONOMETRICS_SKILL_DIR` if set, else finds the Claude Code plugin (`~/.claude/plugins/marketplaces/econometric-skills/econometrics`), any copy under `~/.claude/skills` (including the one synced from the Claude app, `~/.claude/skills/synced/.../econometrics`) or the user's clone, so the user runs the file without editing paths; never put a sandbox path or the versioned `plugins/cache/.../<version>/` folder in it, not even in a comment (in your own environment, set the variable instead). It also turns a missing package into a one-line instruction to run `scripts/setup_env.py --install`. In Claude Code, save the script (and its manifest) in the user's working folder and give its full path, even when the environment offers a scratchpad or temporary directory: a delivered script is the product, not a scratch file; if that folder is a system folder (`C:\Windows\System32`, `/`, the home folder itself) or not writable, ask where to save it instead of using a temporary or scratchpad folder, which the system may delete. and test it on data that include the awkward cases (skipped events, missing values, repeated units).
- **Verify headline numbers by an independent route** (`att_gt`'s `cross_check`, DML vs OLS, a formula vs its simulation, or `reporting.cross_check`) and report agreement; disagreement beyond one SE is a finding. The second route uses a different method or assumptions; the same estimator computed twice (statsmodels vs numpy) only checks the arithmetic and is never reported as an independent confirmation. Agreement means little when the tolerance is a large share of the estimate (report the spread) or when every route is compatible with zero (`reporting.cross_check` flags both). **Relay every diagnostic verdict as printed**, including "inconclusive (low power)"; a script whose output contradicts the text is a failed deliverable.
- **No number from an estimator that did not converge.** Resolve every optimizer warning (iteration limit, non-convergence, singular Hessian) before the number goes into the answer: `quantile_regression` retries and reports `converged` per tau; otherwise raise the iterations, change the solver, or simplify or rescale the model. If it cannot be resolved, say so and leave the number out. Scripts behind a report end with `reporting.run_manifest` (data hashes, versions, seed).
- **No invented numbers**: every figure comes from a computation run in the session or a cited source.
